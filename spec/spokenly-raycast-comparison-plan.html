Spokenly 単語置換 — Raycast Extension 仕様

コピーしました

用語解説

結論: MVP は Raycast Extension（getSelectedText() + Form + open deeplink）とする。Script Command は採用しない。選択テキストは clipboard ではなく getSelectedText で取得する。

概要

目的

任意アプリで選択したテキストを Original に、ユーザー入力した Replacement を Spokenly の Word Replacements 追加フォームを開き、ユーザーが Spokenly 側で Add をクリックして保存する Raycast Extension の仕様を定義する。package manager は pnpm、CI は Mac Studio self-hosted runner（runs-on: [self-hosted, raycast-extension-spokenly-word-replace]）を用いる。lint / format は適用する。Tab 補完後 hook は不適用（今回の利用ツールに必要な hook を設定しないため）。

方式比較（参考: Script Command は不採用）

比較軸 Script Command Extension
選択テキスト取得 公式 API なし。clipboard / {selection} または AppleScript / System Events が必要 getSelectedText() が公式 API
Replacement 入力 @raycast.argument で検索バー入力（最大3引数） Form でバリデーション付き入力
登録起動 シェルから直接 spokenly replacements add open で word-replacements/add deeplink を開く
実装コスト 低（シェル1本、数十分） 中〜高（TypeScript プロジェクト、ビルド・配布）
権限 Cmd+C 経路なら Accessibility 不要。AppleScript 経路は Raycast へ Accessibility / Automation が必要 getSelectedText は Raycast 標準権限内。deeplink は Spokenly アプリ連携
登録方式 CLI で即時登録（確認なし） deeplink でフォーム事前入力（Add は Spokenly 側で手動）

Extension の具体フロー（MVP）

  1. コマンド起動時に getSelectedText() で Original を取得（失敗時は Toast で案内）
  2. Form に Original（読み取り専用）と Replacement（必須）を表示
  3. 送信時に open で spokenly://word-replacements/add?from=…&to=… を開く（from / to は URL エンコード）
  4. 成功 Toast を表示し、Spokenly 側で Add をクリックして保存するよう案内する

deeplink はフォーム事前入力のみで、Add をクリックするまで保存されない。clipboard は使用しない。

Script Command の具体フロー（参考・不採用）

  1. ユーザーが任意アプリでテキストを選択する
  2. Raycast で Script Command を起動（ホットキー可）
  3. スクリプトが osascript 等で ⌘C を送信し、clipboard 先頭を Original として取得（事前に clipboard を保存）
  4. Raycast 引数 UI で Replacement を入力
  5. spokenly replacements add "$ORIGINAL" "$REPLACEMENT" --timing both を実行

本 PJ では Script Command を採用しない。上記は比較検討時の参考情報である。

共通: Word Replacements deeplink と保存動作

Extension は word-replacements/add deeplink で Spokenly の追加フォームを開く。from / to は URL エンコードし、Add をクリックするまで保存されない。 

spokenly://word-replacements/add?from=<original>&to=<replacement>

timing などの詳細設定は Spokenly の追加フォームでユーザーが選択する。comma 区切りの Original（例: raycast, reycast）は Spokenly 側で 複数バリアントとして1ルールにまとめられる。

リスクと対策

リスクと対策

高

Spokenly 未起動

deeplink は必要に応じて Spokenly を起動する。対策: deeplink を開けない場合は明確なエラーメッセージを表示する。

中

選択取得失敗

getSelectedText は未選択で reject → catch して Toast 表示。

中

特殊文字・改行・カンマ

from / to は URL エンコードする。改行や特殊文字を含む Original はクエリ値として壊れやすい → 事前バリデーションで拒否する。カンマは Spokenly 側で 複数バリアント区切りとして解釈される点に注意。

中

重複登録

同一 Original の再登録は上書きか重複か未確認。対策: Spokenly の Word Replacements 一覧で確認してから Add する。

中

CI runner 未登録

self-hosted runner が host に未登録の場合、CI job は queue 待ちのまま進まず merge 不可。runner 登録を merge 前に完了する。

採用方針

MVP 採用

Raycast Extension

  • getSelectedText() で選択テキストを取得（clipboard は使用しない）
  • Form バリデーション・エラー UX
  • pnpm 固定と supply chain 設定
  • CI は Mac Studio self-hosted runner（host runner 未登録なら merge 不可）
  • lint / format を適用
  • Tab 補完後 hook は不適用（今回の利用ツールに必要な hook を設定しないため）

Script Command は比較検討の結果、本 PJ では採用しない。

実装前の検証項目

  • spokenly://word-replacements/add?from=test&to=TEST が手動で Spokenly の追加フォームを開くか
  • 対象アプリ（ブラウザ、エディタ、Slack 等）で getSelectedText が reject しないか
  • Mac Studio self-hosted runner が host に登録済みか（未登録なら CI merge 不可）
  • pnpm install / lint / format / test が self-hosted runner 上で成功するか

受け入れ条件

  • 選択テキストが Original として Spokenly の追加フォームに事前入力される（getSelectedText 経由。clipboard は使用しない）
  • Replacement はユーザーが毎回入力できる
  • Spokenly 側で Add をクリックすると登録される
  • 選択なし・deeplink を開けない場合にユーザーへ分かるフィードバックがある

未確定事項

  • 同一 Original の再登録時の Spokenly 側挙動（上書きか重複か）
  • 改行・タブを含む Original の deeplink クエリ上限とエスケープ規則
  • CI での Raycast UI 手動検証の範囲（mock / deeplink 契約テストとの切り分け）
  • regex 置換や before-ai / after-ai 個別指定の将来ニーズ

開発基盤（bootstrap 実装）

  • Node.js 22.22.2 以上（mise 管理）、pnpm 固定、pnpm-workspace.yaml に supply chain 設定
  • mise.toml タスク: install / dev / check / test / build / lint / format / hooks-install / secrets:scan
  • deeplink 実行層: open（src/lib/spokenly-deeplink.ts）。Vitest で URL 構築を検証
  • CI: Mac Studio self-hosted（runs-on: [self-hosted, raycast-extension-spokenly-word-replace]）。gitleaks のみ。Raycast UI E2E は CI 対象外
  • pre-commit: gitleaks。pre-push: mise run check（lint / format check / test / build。失敗時は push 拒否）
  • lint / format: ESLint（@raycast/eslint-config）+ Prettier。mise run lint / mise run format:check / mise run format。編集後は手動実行（project hooks 未設定）
